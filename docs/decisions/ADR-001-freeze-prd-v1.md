# ADR-001：冻结今日热搜 PRD v1

## 状态

已接受

## 背景

- 今日热搜项目已完成产品范围、MVP、页面状态、验收标准和非目标的初版定义。
- 项目下一步需要进入技术设计对齐和代码初始化阶段，需要稳定的产品边界作为实现依据。
- Owner 已确认冻结 `docs/PRD.md` 为 v1。

## 决策

- 冻结 `docs/PRD.md` 为 v1。
- 后续产品范围、MVP、用户体验和验收标准以 `docs/PRD.md` v1 为准。
- 技术栈、接口、数据模型、缓存实现和部署方案继续由 `docs/TECH_DESIGN.md` 承载，并需要与 PRD v1 对齐。

## 理由与权衡

- 冻结 PRD 可以减少后续实现阶段的范围漂移。
- PRD v1 保留少量待确认问题，允许技术设计阶段继续细化数据源、缓存和部署方案。
- 不把技术细节写入 PRD，避免产品文档和技术设计重复维护。

## 替代方案

- 继续开放 PRD：灵活性更高，但会增加后续开发和审查的不确定性。
- 在 PRD 中同时冻结技术方案：上下文更集中，但会与 `docs/TECH_DESIGN.md` 职责重叠。

## 后果

- 后续功能开发应以 PRD v1 的 MVP 和非目标为边界。
- 若需要改变产品范围、公共体验或验收标准，应先请求 Owner 确认，再更新 PRD 并补充新的 ADR。
- 普通实现细节调整不需要修改本 ADR。

## 替代关系

- 无
