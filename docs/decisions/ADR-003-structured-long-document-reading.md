# ADR-003：结构化长文档按章节渐进读取

## 状态

已接受

## 背景

- 项目正式文档会随需求研究、技术设计和多 Agent 协作逐渐变长。
- 如果所有 Agent 默认全文读取长文档，会增加上下文成本，也容易让简单任务加载无关信息。
- 只按章节读取的前提是文档有稳定章节结构；非结构化文档或全局一致性任务仍可能需要阅读全文。

## 决策

- 对有稳定章节结构的长文档，Agent 应先用 `rg -n "^#{1,6} " <file>` 查看 1-6 级标题，再按任务读取相关章节。
- 如果文档结构不清、局部读取不足、任务涉及全局一致性、架构调整、审查或冲突判断，可以阅读全文。
- 不以节省 token 为由牺牲正确性。
- `docs/TECH_DESIGN.md` 增加阅读导航，作为结构化读取的入口。

## 理由与权衡

- 渐进式读取可以降低多 Agent 开发中的重复上下文消耗。
- 保留阅读全文例外，避免因为过度节省上下文而漏掉关键约束。
- 把行为规则放入 `AGENTS.md`，比只放在单个长文档开头更早生效。

## 替代方案

- 默认全文读取所有正式文档：正确性更稳，但上下文成本高。
- 严格禁止全文读取长文档：上下文成本低，但容易漏读重要约束。
- 仅在长文档内部写阅读导航：对已经全文读取的 Agent 生效太晚。

## 后果

- 后续新增或扩展正式长文档时，应保持清晰的 Markdown 标题结构。
- 简单局部任务优先读取相关章节；高风险或全局任务仍可阅读全文。
- 如果章节导航和正文不一致，应以正文和权威文档为准，并修正文档结构。

## 替代关系

- 无
