# ADR-004：PR 合并后的开发分支保留策略

## 状态

已接受

## 背景

- 项目已确认不直接向 `main` 推送代码，而是通过 `dev/<slug>` 分支和 Pull Request 合并。
- 短期任务分支合并后删除，可以保持远程分支列表清晰。
- 大业务变更可能需要在合并后继续追踪上下文、复盘实现过程，或作为后续迭代的参考。

## 决策

- 短期、小范围开发分支在 PR 合并后可以删除。
- 大业务变更、长期迭代、需要后续追踪或复盘的 `dev/<slug>` 远程分支，PR 合并后可以保留。
- 保留远程开发分支时，应在 PR 或任务记录中说明保留原因。

## 理由与权衡

- 删除短期分支可以减少远程仓库噪音。
- 保留大业务分支可以帮助回看开发过程、比较后续改动，并降低复杂变更的追踪成本。
- 该策略不是强制所有分支都保留，避免远程分支无限增长。

## 替代方案

- 所有 PR 合并后都删除分支：仓库更干净，但复杂业务上下文更难追踪。
- 所有 PR 合并后都保留分支：追踪方便，但远程分支会快速膨胀。

## 后果

- Agent 合并 PR 时不能机械地总是使用删除远程分支选项。
- 对明显的大业务变更，应优先询问 Owner 是否保留远程开发分支，或按任务记录中的约定处理。
- 分支保留策略写入 `docs/AI_WORKFLOW.md`，作为当前有效协作规则。

## 替代关系

- 无
