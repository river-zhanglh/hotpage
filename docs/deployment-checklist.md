# 部署前检查表

日期：2026-06-11

## 1. 构建检查

- 前端：在 `client` 目录运行 `npm run build`，确认 `client/dist/` 生成。
- 后端：在 `server` 目录运行 `npm start` 或部署平台启动命令，确认 `/api/health` 返回 `{ "ok": true }`。
- 本地联调：前端页面能通过 `/api/hot` 获取三平台数据。

## 2. 端口检查

- 前端开发端口：默认 `5173`，以 Vite 终端输出为准。
- 后端开发端口：默认 `3001`，可通过 `PORT` 环境变量调整。
- 本地开发代理：`client/vite.config.ts` 将 `/api` 代理到 `http://127.0.0.1:3001`。
- 启动或重启服务前，先检查目标端口是否已有旧进程监听。

## 3. 前端环境变量

- `VITE_API_BASE`
  - 同域部署时可不设置，让前端继续请求相对路径 `/api/hot`。
  - 分域部署时设置为后端公开地址，例如 `https://api.example.com`。
  - 不应指向微博、知乎、B 站等上游平台地址。

## 4. 后端环境变量

- `PORT`：后端监听端口，默认 `3001`。
- `HOST`：后端监听地址，默认 `0.0.0.0`；本地和多数部署平台通常都不需要设置。
- `CACHE_TTL`：缓存 TTL，默认 `300` 秒，MVP 阶段限制在 `300-600` 秒。
- `CLIENT_ORIGIN`：生产前端域名，用于 CORS 放行，例如 `https://your-hotpage.vercel.app`。
- `WEIBO_HOT_URL`：微博上游地址，仅测试或故障模拟时覆盖。
- `ZHIHU_TOP_SEARCH_URL`：知乎上游地址，仅测试或故障模拟时覆盖。
- `BILIBILI_POPULAR_URL`：B 站上游地址，仅测试或故障模拟时覆盖。

## 5. API 检查

- `GET /api/health`：健康检查。
- `GET /api/hot`：聚合三平台数据。
- `GET /api/hot/:source`：单平台重试，`:source` 可为 `weibo`、`zhihu`、`bilibili`。
- `refresh=1`：开发调试用，跳过后端缓存重新请求上游。

## 6. 回归场景

- 首页三张平台卡片均显示数据。
- 标题点击能跳转到原平台。
- 全页重新加载有 loading 反馈，并且不清空已有卡片。
- 单个平台失败不影响其他平台展示。
- 有旧缓存且刷新失败时，对应卡片显示缓存数据状态。
- 后端挂掉时前端不白屏。
- 手机宽度下卡片单列显示。
- 页脚合规文案存在。

## 7. 合规提醒

- 本项目是个人全栈学习项目，非官方服务。
- 数据来源于各平台公开信息。
- 不在前端直连上游平台 API。
- 不提交密钥、Cookie、Token 或个人账号信息。
